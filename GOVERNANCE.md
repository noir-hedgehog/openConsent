# Governance

openConsent starts with a maintainer-led governance model and moves toward a multi-stakeholder model before 1.0.

- Changes to executable policy controls require two reviewers: one implementation reviewer and one privacy/legal reviewer independent of the author.
- Security-sensitive runtime changes require a security reviewer.
- Material rule decisions, reviewer conflicts, and compatibility impact are recorded publicly.
- Funding and commercial relationships that could influence a rule pack are disclosed.
- A hosted product cannot maintain a secret, weaker version of a public rule under the same control ID.
- Emergency security fixes may merge privately first, followed by an advisory and public patch when safe.

The project still needs named maintainers, a code of conduct, decision quorum, reviewer appointment/removal rules, and an appeal process before accepting a broad contributor community.
